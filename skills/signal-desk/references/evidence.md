# 情报与证据边界

| 状态 | 应如何说明 |
| --- | --- |
| `supported` 有来源支持 | 已识别的一手材料支持引用的具体说法；作者宣传或性能结论尚不等于独立实测 |
| `corroborated` 多源支持 | 至少两组已识别发布者的独立材料支持说法；不同搜索渠道、同发布者多域名与转载不增加独立性 |
| `unverified` 待核实 | 证据或身份不足，保留有价值的线索；不直接称为假消息 |
| `disputed` 存在争议 | 材料有关键矛盾，应展示双方引用和未解决的问题 |

热度（点赞+转发×3+回复×2）、相关性、信息价值、重要性和证据状态是不同维度。关注名单和蓝 V 只用于发现/元数据，不是证据。每项结论的 `articleIds/citations` 指向服务实际返回的原文，不添加未提供的引用。

`contentStatus=snippet/failed` 不表示读取全文；`truncated` 表示只保留部分材料。HN 讨论不等于原始发布，仓库更新时间不等于 Release，累计 Stars 不等于增长。搜索摘要日期不视为可靠发布时间。时间戳是 Unix 毫秒；展示时区明确使用用户时区（项目预算时区 Asia/Shanghai）。

worker 离线、正在采集、初筛、深度核验、队列、预算暂停、等待重试分别根据 `health`、频道有效租约与 `pipeline.activity` 判断。读取情报时没有新上游调用；更新排队、连接配置完成、SMTP 接受均不是最终完成/验证/收件的证明。
