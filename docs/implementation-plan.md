# Signal Desk 实施方案与进度

日期：2026-10-03。用户已授权开始开发；本文件记录最终实现，不要求重复批准设计。用户后续指定 PackyAPI 替代 OpenRouter、X 必需、默认每 30 分钟采集、站内通知与邮件提醒。

## 首版范围

- 用户输入关键词，持续采集新内容，并由 AI 判断语义相关性、聚合事件、解释证据边界。
- 输入关注领域，定期发现并排序热点；完整查询短语可用同义词扩展到英文名称与具体产品。
- 响应式 Web 页面：总览、频道管理、通知、扫描记录、连接设置。
- X 必须作为可用渠道，使用 twitterapi.io Advanced Search；支持 HN、GitHub、RSS 补充。每个频道可选择所需来源。
- 默认 30 分钟，可分别修改频道间隔；新频道默认值可在偏好中调整。
- 网页关闭后，独立后台继续工作。电脑休眠或进程停止时不能继续采集。
- Web 真实功能联调、用户验收后，再封装应用 Agent Skills。

## 设计

采用“编辑部情报台”方向：米白纸面、深绿信号雷达、砖橙色操作、细线与留白；信息按事件和来源依据组织，避免通用仪表盘堆叠。手机使用底部导航，桌面使用侧栏。表单使用原生 dialog，支持焦点约束、键盘与 Escape。

未配置 AI 时展示真实原始候选与待分析数量，不在页面填入模拟热点。测试频道显式标记“验收测试”，保持暂停。

## 技术与执行流程

Next.js 16.3.8 / React 19.3.0 / Tailwind 4.3.3；Drizzle + better-sqlite3；PackyAPI REST Chat Completions；Nodemailer SMTP；独立 Node worker。准确版本由 package-lock.json 锁定，MCP 来源见 api-reference.md。

到期频道 → 来源采集 → 来源 ID 去重及保存检查点 → PackyAPI 分析 → 结构和引用校验 → 事件聚合与热度计算 → 站内通知 → 邮件队列。

SQLite 共 10 张表，保存频道、原文、关联、来源检查点、互动采样、事件、扫描、通知、投递尝试与偏好。事务和 15 分钟租约限制同一频道并发领取；崩溃后旧任务在重新领取时标为中断。Web 与 worker 使用相同配置加载与数据库。

X 用固定窗口、Unix 秒时间参数和 Latest 分页。未完成窗口保留游标，下轮继续；异常游标不覆盖有效恢复位置，失败页也计入请求次数。采集失败不会丢弃已保存的页。来源完整成功才推进相应成功时间边界；有限搜索样本不声明完整覆盖。

AI 每轮默认处理 12 条，剩余候选与失败批次留在队列。热度由相关性、新鲜度、互动、来源多样性及可用增长采样计算；单次采样不编造增长。AI 引用必须存在于采集原文，但这不能证明外部事实绝对正确。

首次扫描读取近期内容建立基线，发布时间早于频道创建的内容不触发历史提醒。待核实提醒默认关闭，争议信息不提醒，冷却期限制重复提醒。SMTP 有有限重试、目标地址接受检查和崩溃租约恢复。

## PackyAPI 替换

已移除 OpenRouter 专属请求字段、请求头和模型预设。配置采用 PACKY_API_KEY、PACKY_BASE_URL、AI_MODEL、AI_OUTPUT_MODE，界面支持接口地址、模型与输出模式切换。

Context7 未提供 Packy 文档，改用 Firecrawl MCP 阅读 Packy 官方资料。官方推荐接口为 https://cf.api.fan/v1，用户给出的 https://www.packyapi.ai/v1 也作为可选地址支持；是否提供对应协议须用真实账户测试。

模型由令牌分组决定；严格 JSON Schema 能力不能由其他平台的支持情况推断。所有输出模式均经过本地校验。不支持格式、认证失败、限流或超时都会显示实际错误。

## 实施边界

首版是本机单用户工具；无登录、公网权限和多租户隔离。热点覆盖受来源、查询词、预算与索引延迟影响。X/AI 不立即自动无限重试，而由后续扫描继续。GitHub 和 HN 超出预算时属于有限样本。人工事实判断仍需结合原始来源。

源码与文档均使用 UTF-8；禁止递归/批量删除；不记录凭证、不向浏览器暴露密钥。技术文档通过 MCP 优先查询 Context7，缺失时使用官方资料的 Firecrawl MCP 查询。
