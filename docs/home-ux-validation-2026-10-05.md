# 首页操作简化与进度展示

日期：2026-10-05。根据用户反馈，解决监控后不知道在哪里阅读、如何刷新以及后台分析状态不明显的问题。

## 用户操作

1. 首页“最新情报”阅读已完成分析的结果，点击卡片查看摘要和原始来源。核验细节按需展开。
2. 选择频道后，“更新情报”会把该频道的采集与 AI 分析一起排队；选择全部频道时只更新运行中的频道。“刷新列表”读取已有结果，不调用外部数据源或 AI。
3. 顶部显示后台停止、采集中、AI 初筛、AI 深度核验、已排队、预算暂停和等待重试。页面可见时每 10 秒同步，切回网页时立即同步；无需反复手动刷新。
4. 频道卡上的“查看情报”直接进入该频道的首页结果，时间范围改为全部时间。频道选择同时影响查看范围和手动更新范围。
5. 首页保留搜索和排序，其余条件集中到“更多筛选”，当前时间范围仍在结果说明中可见。日志、原始材料和队列管理统一在“更新记录”。

移除首页大幅宣传区域、四块统计卡、原始内容列表、重复分析面板与频道侧栏。保留浅色工作台、深色导航和已安装的 Aceternity UI BentoGridItem，用于轻量进度卡，没有添加依赖或重型动画。

## 状态与技术边界

`GET /api/dashboard` 的 `pipeline.activity` 汇总全部未完成任务中的有效租约、待执行、等待重试、预算暂停、失败及暂停频道积压，独立于最近 20 条审计列表。过期租约不显示为正在执行；后台心跳离线时优先显示停止。没有虚构百分比或完成时间。

“更新情报”复用原有 `POST /api/monitors/:id/scan`：原逻辑已同时设置采集请求和显式分析请求。手动更新暂停频道不自动启用其定时任务。没有新增自动启动后台、调整预算或改变可信度规则的逻辑。

通过 Context7 MCP `/reactjs/react.dev` 查询 useEffect 的清理和过期响应处理；安装版本的 Next.js 文档核对客户端数据获取及 Server/Client 边界。轮询清理定时器与可见性监听，使用 AbortController 防止过期请求更新界面；轮询不覆盖设置草稿，筛选失败不误显示其他条件的结果。自动同步没有每轮闪烁的加载提示，手动刷新直到列表完成读取才结束反馈。

ui-ux-pro-max 技能查询命中多步骤进度、提交反馈、加载反馈与 Effect 清理指南。本轮使用渐进展开、明确动词和真实状态反馈，未重建全站设计系统。
